# v0.4 语音陪伴设计

范围：按原功能表的第 3、4 项推进——即时声音回应与语音聊天。现有 v0.3 的电子叫声作为基础，不接入电脑任务执行。

## 架构选择

个人使用的第一版采用手机直连：XR 的 Speech 负责语音转文字，DeepSeek Flash 负责理解和短回复，AVSpeechSynthesizer 负责朗读，现有行为系统负责眼睛、触觉和电子叫声。麦克风录音与人脸跟踪相互独立，默认不给模型上传相机画面。

用户在手机设置中输入自己的 API Key，存入系统 Keychain；不写入代码、UserDefaults 或日志。模型、地址和 Key 可分别配置。默认使用 DeepSeek 官方 HTTPS 地址和 `deepseek-flash`，不依赖 Mac 常开。将来多人分发或由开发者统一提供 Key 时，再增加后端代理。

官方文档确认 Flash 支持思考开关、JSON 输出、流式输出和图像输入。本版只用文本对话，不假设该接口提供原生音频输入或语音合成。

## 交互

- 右下角新增独立的麦克风按钮，和宠物抚摸区域、右上角菜单区分。
- 点击开始听；眼睛立即进入专注状态。显示识别中的一句短字幕，可关闭常驻字幕。
- 再点一次手动发送；也可根据识别内容稳定和静音时长判断结束。短暂停顿不立即截断。
- 首版每轮最多录制约 20 秒，无有效语音约 8 秒后退出。没有识别到内容时不请求模型。
- 识别结果为空或明显不可靠时，询问一次或允许编辑文字，不拿错误转写继续猜。
- 等待模型时用思考眼神和低频动作，不固定播报“让我想想”。
- 回答时根据句子切换眼神和情绪。默认一到两句话，只有用户明确要求才详细展开。
- 说话时点击麦克风：立即停播并开始新一轮；点击宠物：立即停播，同时保留抚摸／逗弄互动。
- 首版播放回答时不录音，避免把自己的声音识别为用户输入。自动语音打断留待回声消除实测后再做。
- 回答结束回到陪伴状态，不默认持续监听；唤醒词和自动连续聊天不进入首版。

## 智能与性格

模型每轮获取：固定性格、最近几轮对话、相关明确记忆，以及少量本地事件摘要。事件如“刚被抚摸”“刚被拿起”“当前在打瞌睡”；不得将其改写为“用户难过”或“用户喜欢我”等无依据结论。

固定性格建议：温和、好奇、稍微俏皮，保留机械宠物身份；自然口语，不每句卖萌、不重复称呼、不把每句回答都变成追问。不编造共同经历，不在用户离开时施压或索取关注。

状态归本地系统管理：精力、注意力、当前交互和打瞌睡不会被模型每轮重置。模型只提供本句的受限情绪提示；抚摸、拿起和用户打断的优先级高于聊天动作。

记忆分成最近对话与长期事实。首版长期事实仅保存用户明确要求记住的称呼、宠物名字和互动偏好，提供查看、修改、删除入口。识别失败的文字不入记忆，被打断的回答不视作已经完整说给用户听。

## DeepSeek 调用

默认关闭思考模式，限制回复长度。第一版用短 JSON 完整回复，校验后再开始朗读，避免播放损坏或未校验的部分 JSON。

```json
{
  "speech": "我在呢。刚刚被你摸得有点想睡觉了。",
  "mood": "relaxed"
}
```

本地验证 speech 非空、长度受限、mood 在白名单中；未知情绪回退平静，空内容、截断 JSON 和服务错误进入可恢复状态。JSON 模式不保证字段符合业务规则，必须自行校验。

短回复实际延迟若达不到目标，再改为流式文本按完整句子朗读；采用有限的情绪标记或独立元数据，不直接朗读 JSON／控制标签。首版不为每轮对话追加独立的情绪识别、记忆总结等多次请求。

保持系统提示与记忆前缀稳定，相关动态事件放在后面，以利用上下文缓存；缓存是否命中以 usage 为准。对话历史设上限，长期运行后压缩旧对话；不依赖模型的百万上下文来堆积全部聊天。

## 语音和声音

用 SFSpeechRecognizer 检查 `zh-CN` 和 `supportsOnDeviceRecognition`。仅在支持时强制本机识别；不支持时明确提示可以使用联网识别或文字输入，不能承诺 XR 上中文一定离线可用。

系统 TTS 先选择已安装的中文声音，提供试听、语速和声音开关。若听感太像播报，再替换独立的中文 TTS 服务；自然音色比给模型添加复杂工具更影响陪伴体验。

录音、TTS、电子叫声统一由一个音频协调器管理。开始录音时停止 TTS 与叫声，停止旧录音引擎并正确处理音频路由变化；切后台、锁屏和系统电话中断时结束当前轮，不自动恢复麦克风。保留前台宠物音效对静音开关的现有行为，并提供“只显示文字”模式。

## 并发与失败恢复

会话状态：陪伴 → 倾听 → 等待 → 说话 → 陪伴。每轮使用独立 turnID；打断时取消识别、网络请求、TTS 队列，所有旧结果即使晚到也不得播放。

用户“停止／安静”等明确指令优先本地处理；其他普通聊天才交给模型。没有主动听取语音的会话时，不因摄像头看到人或环境声音而发起云端请求。

鉴权失败引导检查 Key；余额／限流提示稍后重试；网络错误不无限重试。保留用户已发送的文字供手动重试，不播放半截的失败消息。断网仍可摸、眨眼、看人、发电子叫声。

## 开发与验收顺序

1. API 设置、文字对话、短 JSON 校验、聊天状态与取消机制。用模拟响应测试坏 JSON、超时、限流和旧请求晚到。
2. 中文语音识别与朗读，真机核验可用语言、本机识别能力、首次授权与声音试听。
3. 表情同步、打断、事件摘要、明确记忆和一键清除。
4. 实测停止说话到首句播出的延迟，目标中位数约 3 秒以内；这是待测目标，不是服务保证。

完成标准：一轮录音只发送一次；打断后旧回答不再播放；说话不被自己识别；切后台不继续录音；声音开关、API Key 和会话清除行为正确；人脸跟随及原有抚摸互动不回退。

## 后续目标：唤醒、主人声音与全双工

以下扩展取代“点击麦克风作为最终交互”的预期，点击交互仍作为第一阶段验收和备用入口。尚未实现或在 XR 上验证。

- 本地 TTS：枚举手机实际可用的中文音色和质量等级，提供试听。不能把设置中所有 Siri 音色都假定为 App 可用；对 XR 具体中文音色的听感必须试听。系统语音先保底，表现力不足时再接流式云端 TTS。
- 唤醒词：前台陪伴模式使用小型本地关键词模型；不以持续全文转写和云端 LLM 调用代替唤醒引擎。Porcupine 有 iOS SDK 和普通话模型，可作为候选，采用前需核对许可证、AccessKey 及实际 XR 功耗。
- 主人声音：独立于识别文字。录入多段自然声音，在本机生成声纹模板；对唤醒后的短语和每轮输入做置信度判断。短词不足时先亮眼，待后续语音足够再确认。声纹拒识、误识及录音重放均可能发生，不承诺绝对只听一个人，也不当作安全认证。
- 声纹模板默认仅保存在本机并可删除，录入原始录音不长期保存。旁人模式可手动开启；主人模式默认拒绝不确定输入进入云端聊天。
- 全双工以用户说话能打断为验收重点：同一个 AVAudioEngine 音频链路负责输入、语音处理和播放，开启 voice processing，让回声消除获得自己的播放参考。只设置 voiceChat 不足以自动得到完整语音处理。
- 电子叫声和 TTS 都经过统一播放链路。系统 TTS 应导出音频缓冲后进入该链路，不能继续使用与录音引擎独立的多个播放器来假定 AEC 一定有效。
- 回声处理后的近端语音检测触发降低／暂停播报；声纹和持续说话判断确认后，取消旧 TTS、旧模型请求及待播句子。噪声误触发时恢复，旧 turnID 的迟到结果丢弃。
- 唤醒前保留少量循环音频缓冲用于衔接首句，不写入持久存储。会话结束回到低负载本地唤醒，原始录音不持续上传。
- 唤醒和同时收放音的设计边界是 App 保持前台的桌面模式；锁屏及其他 App 切换后的长期运行需另做系统能力和发布规则验证。

推荐验证顺序：音色试听与基础对话 → 独立验证回声消除和打断 → 接本地唤醒词 → 接主人声纹。即使暂不引入声纹，音频架构也从第一版按全双工目标建设。

## v0.5 实施更新

唤醒采用 sherpa-onnx v1.13.8 的中文 zipformer int8 KWS 模型，约 4.8 MiB。唤醒词“小宠小宠”在本机检测；待机没有全文识别请求。检测后启动苹果 Speech，转写文字交给 DeepSeek，TTS 完成后等 0.35 秒重开识别。8 秒无字或明确结束口令回到 KWS，切后台停止采集，返回前台按开关与已有权限恢复。当前没有预录缓冲，应等界面提示后再说第一句话。

主人声纹按用户要求暂停。全双工开关仍为实验功能，未宣称完成真实环境验收。

真机发现本机 Speech 请求报 201，而用户系统听写开关已开。恢复策略先检查已授权的联网回退；对联网失败不无限重试。不再仅凭 201 推断用户设置。

v0.5.1 补充：唤醒后先说“我在，你说”再聆听，确认语不进入聊天历史。用户已确认实际唤醒和连续聊天可用；不同音色下仍存在漏唤醒样本，后续围绕真实环境改进。

v0.5.2 补充：待唤醒切至 measurement 并关闭 Voice Processing；唤醒后切回 voiceChat，启用处理再播放确认语。保持原关键词阈值。用户对正常音量体验反馈初步改善；未宣称已达到稳定唤醒率。

v0.5.4：推荐词改为“瓦力瓦力”，仍兼容“小宠小宠”；升级 KWS 模型并增加唤醒输入的受限增益与搜索路径。当前代码和 [唤醒测试记录](wake-benchmark.md) 覆盖前文旧的模型大小、关键词与实现参数。真人稳定性必须单独验收。
